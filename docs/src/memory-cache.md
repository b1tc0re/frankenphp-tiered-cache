# MemoryCache

`MemoryCache` — process-local L1. Он ускоряет чтение из Redis, но не является
источником истины и очищается при recovery или invalidation.

## Лимиты и учёт памяти

Стандартная конфигурация использует:

- `DefaultMaxMemoryBytes`: `64 MiB`;
- `DefaultMaxItemSizeBytes`: `4 MiB`.

Нулевые значения конфигурации заменяются defaults. Если общий лимит памяти меньше
`4 MiB`, default-лимит одной записи уменьшается до общего лимита. Отрицательные
лимиты и явно заданный `MaxItemSizeBytes`, превышающий общий лимит, дают ошибку.

`MaxMemoryBytes` учитывает `len(key) + cap(value)` для записей. Он не ограничивает
весь Go heap или RSS процесса.

При нехватке места cache сначала удаляет просроченные записи. Если места всё ещё
мало, он вытесняет живые записи через approximate LRU. Эти вытеснения отражаются
в метриках и в rate-limited warning FrankenPHP. Удаление по TTL, `Forget` и
`Flush` не считается pressure eviction.

## Срок жизни и уборка

Просроченное значение сразу считается отсутствующим. `Get` возвращает miss, а
`Forget` и `Touch` возвращают `false`; физическое удаление и освобождение учтённой
памяти могут произойти позднее.

Одна фоновая goroutine раз в секунду обслуживает LRU clock и постепенно очищает
просроченные записи. Она проходит до 16 из 64 shards за tick и проверяет до 64
записей в каждом shard. Полный обход остаётся отдельным медленным путём при
немедленном pressure eviction.

LRU использует coarse logical clock с шагом `1s`, а не timestamp каждого `Get`.
Несколько обращений в рамках одного tick могут иметь одинаковый `lastAccess`.
Clock локален для экземпляра и не задаёт порядок между процессами.

## Внутренние настройки

Эти параметры не входят в публичный PHP API и сейчас не настраиваются через
environment:

| Параметр | Значение |
| --- | ---: |
| Число shards | `64` |
| LRU samples на eviction | `5` |
| Целевое заполнение после eviction | `95%` |
| Shards на background cleanup tick | `16` |
| Разрешение coarse LRU clock | `1s` |
| Повторные попытки pressure eviction | `3` |

Go integration может передать `Observer` в `MemoryCache`. Callback сообщает об
удалении живых записей после освобождения shard lock; он должен быть быстрым и
безопасным при конкурентных вызовах.
